# macro.lair Instagram 自動投稿

`queue/` に **投稿日をファイル名にした YAML** を置いておくと、GitHub Actions が
毎日 JST 20:50 ごろに起動して、その日の分を Instagram に投稿します。
カルーセル・単写真・リールに対応。投稿直後に「最初のコメント」も自動で置けます。

---

## ⚠️ 先に知っておくこと（3つ）

**① このリポジトリは public にする必要があります。**

Instagram の API は画像のデータを受け取りません。`image_url` を渡して **Meta 側が取りに来る**設計なので、
画像が公開URLに置かれている必要があります。ここでは `raw.githubusercontent.com` を使います。

→ **未投稿の写真とキャプションが、投稿前からネット上で見える状態になります。**
　トークンなどの秘密情報は GitHub Secrets に入るので公開されませんが、下書きは見えます。

**② アクセストークンは60日で切れます。**

`refresh-instagram-token` ワークフローが毎月1日に自動延長しますが、**ここが壊れると静かに投稿が止まります。**
月1回、Actions のログが緑になっているかだけ見てください。

**③ GitHub の cron は遅れます。**

20:50 に予約しても、実際は 20:55〜21:10 くらいに動くことがあります。分単位の精度は出ません。

## セットアップ

### 1. Meta 開発者アプリを作る

1. https://developers.facebook.com/ → マイアプリ → **アプリを作成**
2. ユースケースは **「Instagram を通じて API にアクセス」** を選ぶ
3. 製品から **Instagram** を追加し、**「Instagram ログインによる Instagram API」** を設定
4. **Instagram アカウントを接続**（macro.lair・プロアカウントであること）
5. アクセス許可に以下を含める
   - `instagram_business_basic`
   - `instagram_business_content_publish`
6. トークン生成ツールで **長期アクセストークン（60日）** を発行し、控える
7. 同じ画面に出る **Instagram ユーザーID**（数字の長い列）も控える

> 自分のアカウントに投稿するだけなら、アプリが開発モードでも動きます（管理者／テスターとして紐づいている場合）。
> 一般公開のアプリにする場合のみ App Review が要ります。仕様が変わることがあるので、通らないときは
> アプリの「アプリレビュー」タブを確認してください。

### 2. GitHub リポジトリを作る

- **public** で新規作成（例: `macro-lair-poster`）
- この一式をそのまま push

### 3. Secrets を3つ登録

`Settings` → `Secrets and variables` → `Actions` → `New repository secret`

| 名前 | 中身 |
|---|---|
| `IG_USER_ID` | 手順1で控えた Instagram ユーザーID |
| `IG_ACCESS_TOKEN` | 手順1で控えた長期アクセストークン |
| `GH_PAT` | Fine-grained PAT。このリポジトリに対して **Secrets: Read and write** 権限。トークン自動更新に使う |

### 4. 動作確認

`Actions` タブ → `publish-instagram` → `Run workflow`

- まず **`dry_run` に `true`** を入れて実行。URLの組み立てとキャプションの文字数だけ出て、API は叩きません
- ログに出たURLをブラウザで開いて、画像が実際に表示されることを確認（ここが通れば Meta も取りに来られます）
- 問題なければ `dry_run` を `false` にして本番

## 使い方

`queue/2026-08-21.yml` のように、**投稿日（JST）をファイル名にして**置くだけです。

```yaml
type: carousel        # carousel（2〜10枚）/ image（1枚）/ reel（動画1本）
media:
  - media/2026-08-21_skink_1.jpg
  - media/2026-08-21_skink_2.jpg
caption: |
  本文。改行はそのまま反映されます。

  #タグ #は #末尾に
first_comment: |
  #追加タグ #発見面を増やす実験
```

投稿に成功すると、その YAML は `published/` に移動し、結果の JSON が残ります。
**移動することで二重投稿を防いでいます。** 同じ日に2本出したい場合は、片方を手動で。

### ファイル名は半角英数で

`media/` のファイル名に日本語を使わないでください。URL に日本語が入ると Meta 側の取得が不安定になります。

### 画像・動画の仕様

- 画像: JPEG、8MB以下、アスペクト比 4:5 〜 1.91:1（**1080×1350 はちょうど 4:5 で最適**）
- リール: MP4、9:16（1080×1920）、3秒〜15分、1GB以下
- カルーセルは **2〜10点**。1投稿として数えられます
- 上限は 24時間あたり 100投稿。週2〜3本のペースなら無関係です

## 壊れたときは

**投稿されなかった**

`Actions` のログを見る。よくある原因は次の3つ。

1. トークン失効（`refresh-instagram-token` が失敗していないか）
2. 画像URLが 404（ファイル名のtypo、`media/` に置き忘れ、まだ push していない）
3. アスペクト比エラー（4:5〜1.91:1 の外）

**トークンが完全に失効した**

自動延長では戻せません。手順1のトークン生成からやり直して、`IG_ACCESS_TOKEN` を入れ直してください。
延長には「発行から24時間以上・未失効」という条件があるので、**期限切れの直前に慌てて回しても間に合わないことがあります。**
毎月1日の自動更新に任せるのが安全です。

**急いで手で出したい**

いつでも Instagram アプリから普通に投稿して構いません。その場合は該当の YAML を `queue/` から
`published/` へ手で移してください。移し忘れると翌日に同じものが出ます。
